# P2PChain（骨架）

一个类似比特币的点对点挖矿区块链项目骨架，Go 语言实现，零外部依赖（当前阶段只用标准库），支持普通电脑 CPU 挖矿。

> ⚠️ 这是**学习/实验用骨架**，尚未做安全审计，不要用于任何真实资产场景。核心待办事项见 `docs/DEVELOPMENT_PROMPT.md`。

## 已实现的功能

- [x] 区块结构、区块头哈希、Merkle 根计算
- [x] UTXO 交易结构、Coinbase（出块奖励）交易
- [x] 工作量证明挖矿、难度调整算法
- [x] 内存版区块链（校验前置哈希 + PoW）
- [x] 密钥生成、地址（公钥哈希）、ECDSA 签名/验签（函数已实现，但当前挖矿主流程未调用签名/验签）
- [x] 基于 TCP 的 P2P 传输骨架（连接/帧/广播已实现；当前仅广播区块哈希，接收端尚未做真实处理——跨节点区块/交易同步未实现）
- [x] 内存版区块存储接口（已实现，但尚未接入主链；当前链仅存于内存切片，重启即丢）

## 当前状态与已知限制（诚实说明）

> 本骨架的定位是"教学/实验"，以下事实需与上方勾选项一并阅读，避免误判为可用链：

- **P2P 未实现真实同步**：`broadcastBlock` 仅广播 `{"hash": ...}`，`OnNewBlock`/`OnNewTx` 只是日志桩，接收到的区块/交易不会被反序列化、校验或上链。因此多节点目前各自维护独立内存链，无共识。
- **存储接口未接线**：`internal/storage` 的 `BlockStore` 已实现但未被 `blockchain` 使用，链数据只存于内存切片。
- **钱包签名未接入校验**：`wallet.Sign`/`wallet.Verify` 已实现，但 `ValidateBlock` 尚未调用它们（交易签名/UTXO/双花校验均为 TODO）。
- **无持久化**：重启进程即丢失全部链数据。
- **测试**：PHASE 0 已建立最小测试（`*_test.go`），但本构建环境未安装 Go 工具链，测试尚未实际运行（见 `docs/PHASE-0-ENGINEERING-BASELINE-REPORT.md`）。

## 快速开始

需要本地安装 Go 1.22+（当前沙箱环境未装 Go，代码已人工核对语法但未实际编译，首次运行请先 `go build ./...` 确认）。

```bash
# 启动第一个节点（矿工模式）
go run ./cmd/node --listen :6688

# 启动第二个节点并连接第一个节点
go run ./cmd/node --listen :6689 --seed 127.0.0.1:6688
```

启动后会看到类似日志：

```
[node] 矿工地址（公钥哈希）=3f2a...
[node] 创世区块哈希=00000...
[p2p] 节点已启动，监听地址 :6688
[miner] 开始挖矿，高度=1，难度位数=20
[miner] 挖到新区块！高度=1 哈希=00000... 尝试次数=182933
```

> 注意：以上日志来自单节点挖矿。多节点通过 `--seed` 仅建立 TCP 连接与握手，当前**不会**同步真实区块（见上方"当前状态与已知限制"）。


## 调整挖矿难度（本地测试建议调小）

`internal/pow/pow.go` 中的 `MaxTargetBits` 决定初始难度，数值越大越难。本地单机用普通CPU测试建议先设置为 16~20，观察出块时间后再调整。
